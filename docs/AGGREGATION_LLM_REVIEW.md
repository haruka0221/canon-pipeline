# LLM-Assisted Aggregation Review

## Status

This document records the LLM-assisted review used to adjudicate unresolved
Open Library aggregation units after `project_works_v3`.

The procedure is intentionally conservative. LLM outputs are review evidence,
not project identity decisions by themselves.

Date: 2026-09-27

## Starting point

After aggregation v3:

- current Open Library analysis targets: 34,789
- targets already assigned to project works: 31,783
- unresolved current OL targets: 3,006
- unresolved aggregation units: 1,194
- unresolved external entities in those units: 1,774

The unresolved units were not reviewed manually one by one. Instead, an
LLM-assisted review was introduced as a bounded triage step before freezing the
Open Library / Goodreads / Wikidata identity stage.

## Review task

The LLM was asked to review each unresolved aggregation unit using only the
evidence supplied in the packet.

The main task was to partition the current Open Library target entities at the
level of project conceptual works.

Allowed decisions:

- `ONE_WORK`
- `MULTIPLE_WORKS`
- `UNRESOLVED`

The model also returned:

- clusters of Open Library entity IDs
- relation flags
- confidence (`high`, `medium`, `low`)
- a short evidence summary
- `needs_human_review`

The review was closed-book: the model was instructed not to rely on external
knowledge and to use only the Open Library metadata and existing Goodreads /
Wikidata identity evidence included in the packet.

## Review packets

The production review input was generated by:

`scripts/build_aggregation_llm_review_input_v1.py`

Output:

`derived/identity/aggregation_llm_review_input_v1.jsonl`

Each packet contains, where available:

- current Open Library target records
- title
- author keys
- historical first-publish year
- subject keys
- accepted Goodreads identities and assertion evidence
- accepted Wikidata identities and assertion evidence
- structural classification
- metadata comparison profile

The historical `first_publish_year` is inherited from the frozen Open Library
population construction and is not assumed to be a conceptual original
publication year.

## Pilot review

Before the full review, 30 unresolved units were selected deterministically as
a stratified pilot.

The pilot included examples from:

- `same_title_author_year`
- `same_title_author`
- `same_title_only`
- `different_titles`
- `cross_source_conflict`

The pilot also included units of different sizes, including large multi-record
groups.

### Pilot v1

The first prompt is preserved as:

`prompts/aggregation_llm_review_v1.md`

The first pilot showed that the LLM could identify many straightforward
duplicate-record cases, but it was too willing to return automatic
`ONE_WORK` decisions in some complex cases.

In particular, some cases marked with relations such as translation or
external-source conflict still received `high` confidence and
`needs_human_review = false`.

Examples in the pilot included multilingual/title-variant cases and units in
which Goodreads and Wikidata grouped the Open Library records differently.

The first pilot produced:

- 27 `ONE_WORK`
- 2 `MULTIPLE_WORKS`
- 1 `UNRESOLVED`
- 24 high-confidence results
- 24 results with `needs_human_review = false`

These results were not adopted as project aggregation decisions.

### Prompt v2

The prompt was revised and preserved as:

`prompts/aggregation_llm_review_v2.md`

The revised prompt explicitly required human review when any of the following
relations were present or materially suspected:

- translation
- collection or omnibus
- part-whole
- series or volume
- adaptation
- revised version
- external-source overmerge
- external-source conflict
- uncertain relation

Translations and other complex bibliographic relationships were therefore not
treated as automatically identical project conceptual works.

### Pilot v2

The same 30-unit pilot was rerun using prompt v2 and an independent
deterministic safety gate.

Results:

- 22 `ONE_WORK`
- 2 `MULTIPLE_WORKS`
- 6 `UNRESOLVED`
- 13 high-confidence results
- 11 results with `needs_human_review = false`
- 11 units passed the runner auto-accept gate
- 19 units were held

Previously problematic translation, collection, and cross-source-conflict
examples were no longer eligible for automatic acceptance.

The v2 pilot was therefore accepted as sufficiently conservative for the full
review.

`scripts/run_aggregation_llm_review_full_v1.py`

Prompt:

`prompts/aggregation_llm_review_v2.md`

The runner used structured output and was resumable. Successful results were

## Automatic-acceptance policy

LLM output alone was not sufficient to create a project aggregation decision.

A first deterministic runner gate required a conservative combination of:

- `ONE_WORK`
- high confidence
- no LLM request for human review
- no prohibited relation flags
- no structural cross-source conflict
- no large unexplained first-publish-year discrepancy

This produced 442 candidate units.

A second, stricter adjudication gate was then applied.

To be automatically accepted, a unit had to:

1. pass the runner auto-accept gate;
2. contain the `duplicate_record` relation flag;
3. contain no relation flags outside:
   - `duplicate_record`
   - `title_variant`
   - `authorship_variant`;
4. belong to structural class `multi_ol_no_explicit_split`; and
5. have all current Open Library targets converge directly on at least one
   strong common external identity:
   - a qualifying Goodreads identity, or
   - a high-confidence Wikidata identity.

This reduced the 442 runner candidates to 433 final auto-accept units.

The nine removed units were retained as unresolved because they lacked strong
common external identity support under the final rule.

## Final adjudication

The complete review and deterministic adjudication are frozen in:

- `derived/identity/aggregation_llm_review_adjudication_v1.tsv`
- `derived/identity/aggregation_llm_review_adjudication_v1.parquet`
- `derived/identity/aggregation_llm_review_adjudication_v1_manifest.json`

Final outcome:

- reviewed units: 1,194
- final auto-accept units: 433
- OL targets in final auto-accept units: 923
- held units: 761
- OL targets in held units: 2,083

The 433 units are eligible for promotion to `ONE_WORK` in aggregation v4.

The remaining 761 units are intentionally left unresolved. They are not treated
as errors, negative identity decisions, or evidence that the records represent
different works.

## Interpretation

The LLM review is a triage and evidence-assessment layer, not a replacement for
the project identity model.

In particular:

- an LLM `ONE_WORK` prediction does not automatically create a project work;
- `MULTIPLE_WORKS` predictions are not automatically split into multiple
  project works at this stage;
- `UNRESOLVED` is an acceptable terminal state for the current identity stage;
- translation, adaptation, collection, part-whole, and related bibliographic
  relationships remain distinct from identity unless explicitly resolved by
  project policy;
- Goodreads and Wikidata identities are evidence, not project master IDs.

## Next step

Aggregation v4 will promote only the 433 final auto-accept units to
`ONE_WORK`.

The other 761 units / 2,083 current Open Library targets will remain unresolved
when the Open Library / Goodreads / Wikidata identity stage is frozen.

The project can then proceed to OpenAlex without requiring exhaustive manual
resolution of every remaining Open Library aggregation unit.
