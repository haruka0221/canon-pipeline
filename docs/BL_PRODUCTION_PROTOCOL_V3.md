# BL 本番 v3 プロトコル（production protocol v3）

作成 2026-10-26、確定 2026-10-27。Claude Doc から書き出し。

## 1. 位置づけ

v3 は本番の取得で、v2 の結果（`derived/bl_calibration/calibration_v2/summary.md`、`2ea94aa`）を根拠に設計する。v2 で確かめたのは三つ：`r3_author`（R3＋著者姓一致）は精度 100%（CI 下限 91.2%）で自動採用できる；その再現率は約 37% で、題名の形が違う版（合本・初期版の異題・副題・OL 著者誤り）を落とす；K1 が初版の 10/11 を返し、T2 は 5/11 だった。

v2 から変える点は、採用規則を 2 レーンにすること（§4）、`"` を含む CQL を送る前に仕分けること（§3）、刊本単位で数えること（§6）、監査を 100 件以上にすること（§5）。変えない点は、経路（T2・K1・A1）、照合規則の実装（v1 の関数）、安全装置、非公開保存。

要確認と書いた箇所は、本番の前に決めてコミットする。本文は `docs/BL_PRODUCTION_PROTOCOL_V3.md` として凍結し、取得の前にコミットする（v2 ではコミットが取得後になった）。

## 2. 対象

対象は v2 と同じ `target_frame_v1.tsv`（Project Works v7、`63c3ef6`）の全体。v8 が出ても v3 は v7 に固定し、同定の更新は後で投影する。

| 区分 | 別名行 | 対象数 | 扱い | 値 |
| --- | --- | --- | --- | --- |
| 有効 W | 32,689 | 32,065 | 取得・照合・集計 | 件数（0 を含む） |
| source-light W（Alcott） | 0 | 1 | 検索語がないので対象外 | NA |
| 同定保留 | 17 | 16 | 計測しない | NA |
| 未解決 OL 別名 | 2,083 | 2,083 | 別レーン、W に合算しない | 別名単位の件数 |
| v2 で取得済みの 270 対象 | 278 | 270 | **再取得しない**。v2 の結果をそのまま使い、v3 の規則で再照合する | 同上 |

複数 OL 別名を持つ W（550）は、別名ごとに検索語を作り、どの別名で見つかったかを残す。W 単位の値は刊本単位で重複を除いてから数える（§6）。

要確認：v2 の 270 対象を v3 に混ぜると取得日が違う（2026-10-25 と v3 の各晩）。manifest に取得日を別名単位で残せば問題ないが、BL のレコードが更新されている可能性は注記する。

## 3. 検索経路と CQL 前処理

経路は v2 と同じ T2・K1・A1。v2 で初版を返した経路は K1 が 10/11、A1 が 7/11、T2 が 5/11 だったので、K1 を主経路と位置づけるが、三つとも送る（T2 の完全一致は精度の高い照合の根拠になり、A1 は上限未満の作家で著者全作品を返す）。

前処理（確定、2026-10-26 の読み取りで 286 W・未解決 16 別名が該当）：検索語に `"` を含む論理クエリは**送らずに** `SKIPPED_INVALID_QUERY` として記録する（v2 では `\"` エスケープを BL が拒否した）。該当が 100 W を超えたので、`"` を除いた検索語を **別経路 T2q・K1q・A1q** として送り、元の経路と区別して記録する。照合の規則は元の題名で適用する（検索語の加工は照合に影響しない）。

上限：200 件（方針上）。T2・K1 で打ち切られた対象は `CAPPED` として記録し、v3 でも続きは取らない。A1 は件数確認 → 200 以下のときだけ全件。v2 では A1 の打ち切りが多かった（多作作家）ので、A1 が使えない対象の割合を層別に報告する。

検索語の作り方、正規化、物理クエリの重複除去は v2 のスクリプトと同一（`run_bl_calibration_v2_v1.py` の `build_plan`）。v3 の実行スクリプトはこれを継承し、対象の範囲と前処理だけを足す。

## 4. 採用規則：2 レーン

対象 × レコードのリンクを、v2 で凍結した規則（exact / r3 / author / r3_author、v1 の関数を import）で分類し、三つに分ける。

| レーン | 条件 | v2 での VALID 率（S1+S2） | v3 の扱い |
| --- | --- | --- | --- |
| A 自動採用 | `r3_author` 真 | 100%（CI 下限 91.2%） | 判定なしで採用。`accepted` |
| B 判定 | `r3` 真かつ著者不一致 | 22%（12–33%） | 標本を LLM 判定＋人間監査し、層別の VALID 率を推定（§5）。`judged` / `estimated` |
| C 判定 | `r3` 偽（K1・A1 だけで返った） | 8%（2–16%） | 同上。ただし母集団が大きいので層を細かく切る |

レーン B・C の個々のリンクは、標本に入ったものだけ `judged`（LLM＋監査の結果を持つ）、入らなかったものは `estimated`（層の VALID 率を持つ）になる。W 単位の値には両方を使う（§6）。

著者一致の規則は v2 と同一だが、**著者の上書き表**を足す。初期行は v2 の判定の注記から 4 件（2026-10-26）：`W000008880` *Life with Father* は O. Henry → Clarence Day；`W000015492` *Red Riding Hood* は R. André が挿絵者で著者なし（著者条件を外す）；`W000004947` は Rives に Wheeler を追加；`W000028112` *So Great a Man* は筆名 David Pilgrim に Palmer・Saunders を追加。各行に根拠を書き、取得の前に凍結する。表は完全でなくてよく、上書き表に入らない誤りはレーン B に落ちて判定で救われる。v3 の判定レーンで見つかった誤りは v4 用に追記する。

規則そのもの（r3 の実装、著者一致の定義）は v3 で変えない。変えると v2 の精度推定が使えなくなる。

## 5. 判定レーンの標本設計と推定

規模の見込み（v2 の S1+S2、250 対象の比率を 32,065 W に当てはめる）：レーン B 約 76,000 リンク（1 対象 2.4）、レーン C 約 1,600,000 リンク（1 対象 51、大半は A1 で返った著者の別作品と K1 の雑音）。全件判定は無理なので、層化標本で VALID 率を推定する。

層は、レーンごとに「返した経路」と「レコードの年代（008 の年が 1950 年より前か）」で切る：

| レーン | 層 | 根拠 |
| --- | --- | --- |
| B | T2 も返した／K1 だけ／A1 だけ × 1950 年前／後 | v2 で古いレコードほど 245 の形が違う |
| C | K1 で返った／A1 だけ × 1950 年前／後 | A1 だけのレコードは著者の別作品が大半の見込み |

標本の大きさ：レーン B 250、レーン C 250、各層に最低 40 を割り当て、残りを層の大きさに比例配分。1 対象あたり最大 5 リンクまで（多作作家に偏らないため）。種は固定。判定は v2 と同じ指示文を v3 用に改訂したもの（他人による脚色の分類を追加、v2 summary §6 の 6）で LLM が一次判定し、人間が各レーン 60 件（LLM VALID / INVALID / UNCERTAIN から層別）を盲検で監査する。合計 LLM 500、人間 120。この大きさは、推定分を感度分析にだけ使う（§6）前提で決めた。推定分を主分析に使うなら各レーン 400・人間 100 に増やす。

推定は v2 の `analyze_bl_calibration_v2_v1.py` と同じ式を層ごとに適用する：P(VALID | 層) = Σ P(LLM ラベル | 層) × P(人間 VALID | LLM ラベル)。CI はブートストラップ、全 VALID の層は Clopper–Pearson 下限。監査が 40 件だった v2 の弱点に対し、v3 は LLM VALID の監査だけで 100 件以上を確保する。

標本は本番の取得が**全部終わってから**抜く（途中で抜くと取得順に偏る）。したがって判定は取得の 22〜25 晩の後。取得と判定の間に規則を変えない。

確定（2026-10-26）：v2 の判定で A1 だけのレコードは J3 の中で LLM VALID 2.8%（2/72）、人間監査 13 件は全部 INVALID。事前基準（2% 以下で外す）をわずかに超えるので、レーン C の独立した層として残す。配分は最低の 40 件とし、v3 の人間監査にこの層を必ず含める。

## 6. W 単位の値の定義

数えるのはレコードではなく刊本。v2 の鍵（正規化 245a ｜ 出版者 ｜ 年）で同一刊本のレコードをまとめ（v2 では r3 真の刊本 2,205 のうち 206 に重複レコード）、刊本に対してレーンの結果を付ける。刊本の中に `accepted` が 1 件でもあれば `accepted`、なければ `judged` の結果、なければ `estimated` の率。

W ごとに出す値は三つに分け、ひとつに足し込まない。**主分析は `accepted` ＋ `judged_valid` だけを使う**。`estimated` は感度分析に使い、層ごとの VALID 率と 95% CI を付けて「推定分を足しても結論が変わるか」を示す。

| 値 | 中身 | 性格 |
| --- | --- | --- |
| `bl_pub_accepted` | レーン A の刊本数 | 確定（精度 100%、下限 91%） |
| `bl_pub_judged_valid` | レーン B・C で標本に入り VALID と判定された刊本数 | 確定（個別判定あり） |
| `bl_pub_estimated` | 標本に入らなかったレーン B・C の刊本に、層の VALID 率を掛けた期待値 | 推定（層ごとの CI を持つ） |

併せて、刊本の関係の分布（`target_alone` / 合本 / 翻訳 / 抄訳 …）と、年代別の刊本数（008 の年で 10 年刻み）を `accepted`＋`judged_valid` について出す。これは OL の `edition_decades` と並べて比較するための形。

複数 W で r3 真になるレコード（v2 で 117 件）は、`multi_w_candidate` として各 W の値に**仮に**含め、件数を W ごとに別列で持つ。どの W に帰属させるかは identity review の判断（Heart of Darkness の 4 W など）で、v3 では決めない。

ゼロと NA を分ける：レコードが返らなかった W は 0、同定保留・source-light は NA、`"` で題名経路を送れなかった W は `title_routes_skipped=true` を付ける。

## 7. 規模・日程・安全装置・実行環境

規模（確定、2026-10-27 のクエリ計画 `5cb5374`）：対象 33,878（有効 31,797＋未解決 2,081、v2 の 270 を除く）、論理クエリ 102,565、物理クエリ 85,020、引用符仕分け 591。v2 の実測（物理 1 本あたり 1.77 リクエスト、A1 の件数確認とページ送りを含む）から **約 15 万リクエスト**。上限は 20 万。

日程：1 晩 22:00–06:00 London の 8 時間、応答後 3 秒で最大約 9,000 回だが、v2 の実測（1,384 回で約 3 時間強）から 1 晩 7,000 回を上限にすると **22 晩**（1 バッチ ≈ 4,400 回、1 晩に 1〜2 バッチ）。連続で約 3 週間、週 5 晩なら 4〜5 週間。英国が冬時間なので日本時間 07:00–15:00。

安全装置は v2 と同一：逐次、応答後 3 秒以上、22:00–06:00 London のみ、429 / 5xx / 接続エラー / diagnostic で即停止・自動再試行なし、1 晩の上限 7,000、累計上限 20 万、完了ページの再送なし。加えて：

- 対象を **1,000 W ずつのバッチ**に分け、バッチごとに status と manifest を書く。途中で止まっても完了バッチは確定。
- 1 晩の始めに前夜のログの整合（行数・重複なし）を自動で検査してから送る。
- 1 晩の終わりに、その晩のリクエスト数・停止の有無・raw の sha256 を manifest に追記する。

実行環境：サーバー（`~/canon-pipeline-bl`、`tmux`）。raw は `/media/hdd1/user/tsutsui/bl/production_v3_raw/`（700）、解析済みは `.../production_v3_derived/`。起動は `sleep` で 07:00 JST を待つ形にし、人が毎朝起動しなくてよいようにする（停止したときだけ人が再開）。ログと status は公開リポジトリにコミットできる（レコード本文を含まない）。

要確認：BL が「25 晩連続」を問題にするか。v2 の通知には異議がなかったが、本番は規模が 100 倍なので、§9 の連絡で期間と 1 晩の上限を明示し、了承を待ってから始める（v2 と違い、返事を待つ）。

## 9. BL への連絡

本番も v2 と同じく**通知のみ・返事不要**で行う（9 月の BL の返事「SRU で個別に検索するのはご自身でできる」と、v2 通知への異議なしを根拠にする）。ただし開始日は送信から **1 週間以上あと**にし、止めたければ止められる時間を置く。内容：v2 の結果（1,384 回、エラーなし）を短く報告し、本番の規模（約 15 万回、上限 20 万）、1 晩の上限（7,000 回）、時間帯（22:00–06:00 UK）、期間（約 22 晩、週 5 晩で 4〜5 週）、開始予定日、送り方（v2 と同じ）、データの扱い（非公開保存、公開は W 単位の集計のみ）を伝え、時期や頻度の希望があれば合わせると書く。

BL から停止や変更の求めがあれば従い、その内容と日付を manifest に記録する。開始後に求めがあった場合は、その晩の分まででいったん止め、調整してから再開する。
