# BL 本番 v3 プロトコル 改訂 1：network 停止時の同一バッチ自動再開

日付：2026-11-01
対象：`docs/BL_PRODUCTION_PROTOCOL_V3.md` §7（安全装置）。凍結文書と `protocol_freeze_v1.json` は変更しない。

## 理由

本番 4 晩のうち 2 晩で、BL 側の一過性の切断により夜の取得が止まった。

- 2026-10-30 10:02 JST：`http.client.IncompleteRead`（応答の途中で接続が切れた）
- 2026-11-01 08:06 JST：`RemoteDisconnected`（応答なしに接続が閉じられた）

いずれも 429 や 5xx ではなく、こちらの送信量とは無関係の切断。凍結規則では network エラーで夜を終了し翌日は手動再起動のため、見落とすと夜間窓の大半を失う。

## 変更

driver（`scripts/bl/bl_v3_nightly.sh`）に限り、runner の停止理由が `STOP_NETWORK` のときは 10 分待って同じバッチを再開する。1 晩に最大 2 回。3 回目の network 停止は従来どおり夜を終了し、翌日も自動では動かない。

## 変わらないこと

- runner の `retries=0`：個々のリクエストは再試行しない。失敗した 1 クエリは再開後に改めて送られる（完了済みクエリは runner の request log から復元され、再送されない）。
- 夜間窓（London 22:00–06:00）、1 晩 7,000、累計 200,000 の上限。再開後の送信も同じ夜の数に加算される。
- `STOP_HTTP`（429・5xx など BL からの明示的な応答）、diagnostic、parse エラーでの即時終了。
- BL への通知内容（送信量・時間帯は変わらないため追加の連絡はしない）。
